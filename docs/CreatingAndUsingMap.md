# マップファイルの作成と利用方法

`TMappingProcessor` はセグメント化された未分類データを、マップ設定ファイルとマップファイルを読み込んでカテゴリ付きデータへ変換する処理器です。本稿では `mapper.conf` の書式と、実際のマップファイルの構造・書き方を説明します。

## マップ設定ファイル（`mapper.conf`）

マップ設定ファイルは「マップファイル名」と「そのファイルで処理する行数 `ndata`」の組を列挙します。`TMappingProcessor` はトークンが欠けるまで読み取り、列挙された順にマップファイルをロードします。

例:

```
# mapper.conf
example.map 1
```

この設定では `example.map` を読み込み、カテゴリ／検出器の組ごとに 1 行ずつマップ情報が記載されていると解釈します。

## マップファイルの構造

各マップファイルは `#` をコメントとして扱い、カンマ・空白・タブを区切り文字として読み込みます。パーサは次の順にトークンを処理します。

1. カテゴリ ID (`cid`) と検出器 ID (`did`) の 2 つの整数。
2. 続けて `ndata` 行の 5 整数を読む: `ids[0]`–`ids[2]`（セグメント識別子）、`ids[3]`（geo/モジュール）、`ids[4]`（チャネル）。読み込み回数（0 始まり）がそのまま `type` として保存されます。

RIDF 入力では `ids[0]`–`ids[2]` をビットシフトしてセグメント ID を構成し、RDF 入力では `ids[2]` がセグメント ID になります。各行は「セグメント → geo → チャネル」の三段階テーブルを埋め、カテゴリ ID・検出器 ID・タイプを対応付けます。重複がある場合はエラーとなります。

## 記述例: カテゴリ 51、検出器 ID 0–9 を geo `0x29a`、ch 10–19 に割り当て

以下はカテゴリ 51 の検出器 ID 0〜9 を、`ids[0]`–`ids[2]` を 0、`ids[3]` を `0x29a`、`ids[4]` を 10〜19 に設定する例です。`mapper.conf` では `ndata` を 1 にしているため、カテゴリ／検出器の組ごとに 1 行だけマップ情報を書きます。

```
# example.map（上記 mapper.conf を使用）
51 0    0 0 0 0x29a 10
51 1    0 0 0 0x29a 11
51 2    0 0 0 0x29a 12
51 3    0 0 0 0x29a 13
51 4    0 0 0 0x29a 14
51 5    0 0 0 0x29a 15
51 6    0 0 0 0x29a 16
51 7    0 0 0 0x29a 17
51 8    0 0 0 0x29a 18
51 9    0 0 0 0x29a 19
```

各行の先頭 2 つの整数がカテゴリ ID と検出器 ID に対応し、後続の 5 整数がセグメント ID（0）、geo `0x29a`、チャネル 10〜19 を指定しています。`ndata` が 1 のためタイプはすべて 0 となり、このセグメント・geo・チャネルに一致する未分類データはカテゴリ 51 の指定した検出器 ID とタイプ 0 で分類されます。
